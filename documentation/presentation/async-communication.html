Asynchronous communication (RabbitMQ)

Proposed RabbitMQ flow after an incident is verified. The incident service publishes an event for recovery planning and optional biodiversity follow-up.

PNG image Download the draw.io file

Diagram toolbar: zoom, change page, full screen. The pencil opens an editable copy in diagrams.net. Without an Internet connection, the PNG image is shown instead.

Topology

ComponentProposed contractPurpose
Producerincident-servicePublishes after an incident reaches VERIFIED.
EventIncidentVerifiedCarries the incident ID and the forest zone ID.
BrokerRabbitMQRoutes the message to consumers.
Consumerrecovery-serviceRecords the incident reference for planning.

Design rules

  • Publish the event after saving the verified status.
  • A consumer should tolerate repeat delivery.
  • The recovery service still owns recovery project creation.

Include RabbitMQ in the proposed Docker Compose setup. The diagram shows proposed exchange and queue names, plus a dead-letter path for rejected recovery messages.
